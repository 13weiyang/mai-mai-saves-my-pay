# Agent 对话示例

> 展示这个 Skill 在真实对话里怎么用。**每条都照着 `skill/mai-mai-saves-my-pay/SKILL.md` 的流程走。**

---

## 示例 1 · 最基础：「预算 300 吃麦当劳，怎么点最省」

**用户**：我想吃麦当劳，预算 300，怎么点最省？

**Agent**：
**第一步先定门店** —— 你没说哪家，我按"北京"找了 3 家最近的：

| 门店 | 距离 |
|---|---|
| 麦当劳北京嘉秀路餐厅 | 15 米 |
| 麦当劳北京建外SOHO(A座)餐厅 | 8.4 公里 |
| 麦当劳北京善缘街(中关村5号)餐厅 | 18.4 公里 |

选哪家？

（用户选第 1 家后）拉菜单 + 活动 + 可用券 → 算完报账：

| | |
|---|---|
| 原价合计 | ¥347.50 |
| 用上活动 | 满 300 减 22% |
| **实付** | **¥271.05** |
| **省下** | **¥76.45** |

> **⚠️ 关键**：报的是**实付**，不是原价 —— 因为"预算"是"我打算掏多少钱"。

## 示例 2 · 带娃：「一家三口，孩子两个」

**用户**：一家三口，两个娃，预算 500。

**Agent**：
**先问一句**：要「亲子餐」还是「成人+亲子」？

- **亲子餐** = 大人那份优先成套/分享（一家人摆一桌）
- **成人+亲子** = 大人那份单品自由（想点单只汉堡也行）

选定后：

- 方案里**自动带官方「开心亲子双人餐」**（1 大 1 小成套，含玩具）
- 菜单里儿童餐**置顶成一组「🧸 让孩子先选」** ——
  因为**一家人点餐，一般先问孩子想吃什么**

> **⚠️ 关键**：儿童餐份数**锁死 = 儿童人数**，不会多凑出一份
>（多一份就是多花一份钱 + 一个重复玩具）。

## 示例 3 · 套餐自选：「我要自己挑那 7 件」

**用户**：堡堡随心拼那个，7 件我想自己挑。

**Agent**：打开选择面板 ——

```
第1轮 主食任意选        已选 2/2
   麦辣鸡腿汉堡 / 板烧鸡腿堡 / 巨无霸 / 双层吉士汉堡
第2轮 选择随心配小食    已选 3/3
   麦辣鸡翅2块 / 麦乐鸡5块 / 麦麦脆汁鸡-琵琶腿 / 奥利奥麦旋风 / 中薯条
第3轮 选择套餐内饮料    已选 2/2
   可乐中杯 / 雪碧中杯 / 阳光柠檬红茶中杯 / 黄金橙橙 / 锡兰红茶
```

> **⚠️ 关键**：
> - 默认就是**官方默认搭配**（不是 Agent 瞎猜的）
> - **每轮必须选够件数**（官方规则是"正好选 N 件"）
> - **换贵的选项价格当场涨**（换 +¥2 的饮料 → ¥57.50 变 ¥59.50）
> - **只有真拿得到数据的款才给这个入口** —— 没数据的不装、不编

## 示例 4 · 下单（最重要的一段）

**用户**：就这个，下单。

**Agent**：**先把这一单原样复述一遍，你确认了才动** ——

```

取餐：堂食 · 店内用餐

  BFF四宫格小食盘双人餐      ×1   ¥123.00
  堡堡随心拼（7件任选）       ×1   ¥103.00
  薄皮V翅双拼十翅           ×1    ¥74.50
  安格斯厚牛堡四件套随心选     ×1    ¥66.50
  蘸酱麦麦脆汁鸡            ×1    ¥18.00
原价合计：¥347.50
用上活动：满 300 减 22%
官方实付：¥271.05
```

**确认下单吗？**

（用户回"确认"后）

**Agent**：下好了。**这是麦当劳官方的支付链接** → [链接]

支付在麦当劳官方渠道完成，**我们不经手钱**。

> **⚠️ 三条红线**：
> 1. **无确认绝不下单**（`create_order()` 必须显式传 `confirm=True`）
> 2. **绝不代付** —— 只把官方链接原样交给你
> 3. **Token 绝不进仓库**

## 示例 5 · 一个必须诚实回答的问题

**用户**：帮我用券，能省更多吧？

**Agent**：这里得说实话 ——

> 接口**支持每个商品挂一张券**（`couponId` / `couponCode`），
> **但"券能不能和门店满减叠加"，我们还没实测过**。
> 所以现在只能给你「活动省多少」，**券那一层是空的**。

> **⚠️ 关键**：**没验过的标"待实测"，不说"已经好了"。**
