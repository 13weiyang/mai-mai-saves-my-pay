# 麦门搭子 · 说一句，麦麦就到

麦当劳点餐助手。基于**麦当劳官方 MCP**，让用户在电脑上**说一句就下单**——
不用掏手机、不用看 App 上那堆小字、不用跟人开口。

> ⚠️ **名字待定**（"麦门搭子"是暂用名），立意已定。

## 一、它为什么存在

坐在办公室想吃麦麦时，用户（尤其 i 人）的真实处境：

- **不想掏手机**（手机静音躺在一边）
- **不想看 App 上那堆小字**
- **不想打电话、不想跟店员开口**

而这个 Skill 只要一句话：

> 「**来份巨无霸，再来个冰美式中杯**」

**⇒ 不碰手机、不开口。剩下的它全干了。**

## 二、什么时候用它

| | |
|---|---|
| ✅ **用** | 麦当劳点餐（到店自取 / 麦乐送）· 领券用券 · 查门店菜单价格 · 下单前核对 |
| ❌ **不用** | 营养/热量建议；非麦当劳品牌点餐 |

## 三、怎么用

```bash
# ★ 第一步：先看看有什么（不知道吃啥时，一定先来这个）
python mai_mai.py --store <门店编码> --show

# ★ 主路：说要什么（不用报预算）
python mai_mai.py --store <门店编码> --items "巨无霸,冰美式中杯"

# 主路 + 真下单（会二次确认）
python mai_mai.py --store <门店编码> --items "巨无霸" --order --takeway eat-in

# 找店（不知道门店编码时）—— 列出最近的几家，带店名/地址/距离
python mai_mai.py --city 北京 --keyword 嘉秀

# 外送（会先问「自取还是外送」，再逼你确认收货地址）
python mai_mai.py --city 北京 --keyword 嘉秀 --items "巨无霸" --order --delivery
```

> **「说一句就下单」的前提是用户知道要什么。**
> **不知道吃啥 → 先 `--show` 看图（有图才有食欲）；知道了 → 再 `--items` 点。**

🎫 **券是自动的**：跑 `--items` 时，它**先替你把能领的券全领了**，再把这一单能用的券**挂上去** ——
你不用知道有什么券。

⚠️ **关键词填"用户所在的片区名"**（如"嘉秀""果园"），不是随便一个地名——
门店接口返回的距离是「离这个地名」的距离（见第六节坑 7）。
**只给 `--store <编码>` 时拿不到店名/地址，CLI 会明确警告，下单前务必人工确认。**

- Token：环境变量 `MCD_MCP_TOKEN`，或读上级目录 `mcd-token.txt`；⚠️ **绝不进仓库**

## 四、标准流程

| # | 做什么 | MCP 工具 |
|---|---|---|
| 0 | 🔴 **先问：自取 还是 外送？** —— 不是"送不送"的区别，是**两套门店、两套价**；没指明就别默认 | — |
| 1a | **定门店（自取）** —— 按片区搜，列最近几家（带店名/地址/距离），默认最近的 | `query-nearby-stores` |
| 1b | **定门店（外送）** —— 🔴 **先确认收货地址**，再查该地址可配送的门店（外送要 `beCode`，不是门店编码） | `delivery-query-addresses` / `delivery-query-stores` |
| 2 | **看菜单** —— 自取 / 外送是**两套菜单**，别混 | `query-meals` / `query-meal-detail` |
| 3a | 🎫 **替用户领券** —— **不是"提醒他去领"**：理想用户不会因为一句提示就去领券（她连有什么券都不知道）。领完**回读卡包张数**，报"新领 N 张 / 无券可领" | `auto-bind-coupons` |
| 3b | **挑券并挂上** —— 查「这单能用哪张」，挂到**对应商品**上；🔴 **份数 > 1 的商品不挂**（见坑 9） | `query-store-coupons` |
| 4 | **算价** —— 自取报「原价 / 省多少 / 实付」；**外送要拆开「商品 / 配送费 / 打包费」** | `calculate-price` |
| 5 | 🔴 **确认门店** —— 把「**店名 + 地址 + 距离**」摆出来让用户点头（**别只报编码**） | — |
| 5b | 🔴 **确认收货地址（外送必做）** —— 摆出「联系人 + 电话 + 完整地址」，用户点头才往下 | — |
| 6 | ⚠️ **复述整单**（门店 / 取餐方式 / 清单 / 实付），用户确认 | — |
| 7 | **下单** —— 拿 `payH5Url` 交给用户，**用户自己付** | `create-order` |

> **第 5 / 5b 步不是走过场**：**光看清单不够 —— 地址才是能认出"哪家店 / 送到哪"的东西。**
> **到店走错了还能走去另一家；外送送错了，菜就凉了。**

## 五、⚠️ 五条红线

1. **绝不代付** —— 只把官方支付链接交给用户；**付款是唯一不可逆的一步，必须用户亲手按**
2. **绝不无确认下单** —— `confirm=True` 才创建订单，确认前什么都不发生
3. 🔴 **绝不跳过「确认门店」** —— 必须把「店名 + 地址 + 距离」报给用户核一遍；
   **只报门店编码 = 没确认**（用户认不出编码，是出错的重灾区）
4. 🔴 **外送绝不跳过「确认收货地址」** —— 地址是外送唯一"送错就回不了头"的东西
5. **Token 绝不进仓库**

## 六、⚠️ 必须知道的坑（全部实测过，照抄结论即可）

1. **别调 `query-promotions`**
   那是**企业团餐（beType=6）专属**规则，入参写死 `beType=6`。
   普通到店 / 外送调它，拿回来的是用户**用不上**的优惠，算出来的"省"是虚的。
   ⇒ **普通点餐的优惠只有两样：门店现价折扣 + 券。**

2. **菜单上的"现价"约 45% 是虚的**
   部分"多件套"标着现价（如八件套 49.9），接口实付却是原价 115.5。
   ⇒ **算价一律以 `calculate-price` 返回为准**，别信菜单的现价字段。

3. **下单返回的支付链接字段名是 `payH5Url`**
   （不是 payUrl / payLink / url —— 找错名字会误判成"没有支付链接"）
   订单里还有 `totalAmount` / `realTotalAmount` / `totalDiscountAmount` / `couponList`，
   **"省了多少"直接读 `totalDiscountAmount`**，不用自己算。

4. **菜单分时段** —— 早餐时段查不到汉堡和儿童餐，**不是下架**。

5. **用户说法 ≠ 菜单名**
   「冰美式中杯」→ 菜单叫「**麦咖啡™美式**」；
   「全明星八件套」→「全明星双人分享餐八件套」。
   ⇒ 匹配要**去掉规格词**（中杯/大杯/冰/热/™），再做字符相似度。
   CLI 已内置（`find_meals_by_names`）。

6. **券和门店价可以叠加**（已实测）：券作用在单品、门店价作用在同一单品，
   两者**各减各的**。当前门店可用券用 `query-store-coupons` 查（不是 `query-my-coupons`）。

7. **门店距离是「离你给的那个地名」的距离，不是「离你本人」**
   `query-nearby-stores` 不认经纬度，只认「城市 + 地名」。
   同一家九棵树餐厅：关键词给「九棵树」是 **49 米**，给「果园」就变 **987 米**。
   ⇒ **想让"离我最近"成立，关键词必须填用户所在的片区名**；
     真要在浏览器里定位，得先「坐标 → 反查地名」，再把地名喂进去（接口不给经纬度）。

8. **外送单的 `originalPrice` 含「配送费 + 打包费」**（2026-10-10 实测）
   例：巨无霸 2900 + 配送 600 + 打包 110 = **3610**（¥36.10）。
   ⇒ **别把"商品 + 运费 + 打包"一起当"原价"报给用户**，那会让人以为商品卖 36 块。
   ⇒ 外送必须拆成三项：**商品合计 / 配送费 / 打包费**。
   外送还**必须有 `beCode`**（来自 `delivery-query-stores`），缺它会被拒。

9. 🔴 **挂券会把该商品的份数吃成 1**（2026-10-10 实测 · **事故级**）
   ```
   不带券：冰美式 x1 原价1900 ｜ x2 原价3800 ｜ x3 原价5700
   带  券：x1 / x2 / x3 原价**全是 1900**      ← 份数没了
   ```
   ⇒ **用户想买 3 杯、挂上券 → 只给 1 杯。**
   ⇒ **份数 > 1 的商品一律不挂券**（要么别挂、要么拆成多行）；
     CLI 已内置这道闸门（`attach_coupons`），**并会明说"没挂、为什么"**。
   ⇒ 券是**商品级指定特价**（一个商品只挂一张）；拿不到 `couponId` 就**不挂、不编**。

## 七、两个容易搞反的口径

- **别把"券"说成"满减"** —— 用户听得懂"领张券省 2 块"，听不懂"满减门槛"。
- **别把"能传券"说成"能叠加"** —— 叠加要实测过才能说（现已实测：可以）。
